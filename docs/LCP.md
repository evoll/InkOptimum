# Readium LCP

Книги с LCP открываются через сервис FreeInk (`https://lcp.freeink.org`). Устройство не знает схемы защиты: оно получает ключ контента, а читалка расшифровывает книгу на лету (см. `docs/plugin-hub.md`, `<книга>.key`).

## Поток в OPDS-браузере
1. Ссылка каталога с типом `application/vnd.readium.lcp.license.v1.0+json` показывается как формат **LCP** (OPDS 1.x и 2.0).
2. Лицензия `.lcpl` скачивается с учётными данными каталога.
3. `POST /fulfill` (тело — лицензия) возвращает EPUB с вшитой лицензией. Файл идёт через `<имя>.part` и проверяется на ZIP.
4. Пароль: сохранённый для провайдера хэш пробуется первым, иначе экран ввода с подсказкой из лицензии (`text_hint`).
5. `POST /unlock {device_id, user_key (hex SHA-256 пароля), license}` возвращает `{content_key:{epk,iv,ct,tag}, expires}`. Ключ завёрнут (X25519 + HKDF-SHA256 + AES-256-GCM) на ключ этого устройства и открывается им.
6. Ключ сохраняется как `<книга>.key` (с обёрткой ключом устройства); срок берётся из `expires`.

Коды `/unlock`: 401 — устройство неизвестно (идентичность сбрасывается и происходит повторная регистрация), 403 — неверный пароль, 422 — профиль, который сервис не обслуживает.

## Регистрация устройства
`POST /enroll {release_key, pubkey}` -> `{device_id}`. Пара X25519 создаётся при первом использовании; закрытый ключ лежит в `/.inkmod/lcp_device.json`, обфусцированный ключом устройства, хэши паролей по провайдерам в `/.inkmod/lcp_passphrases.json`. Оба файла закрыты для веб-доступа и сохраняются при очистке кэша.

Регистрация требует release-ключа сборки: `-DFREEINK_LCP_RELEASE_KEY=\"...\"` (в CI секрет `FREEINK_LCP_RELEASE_KEY`, передаётся через `PLATFORMIO_BUILD_FLAGS`). Ключ выдаёт владелец сервиса.

## Самосборка без release-ключа
- Лицензия basic-профиля (`http://readium.org/lcp/basic-profile`) открывается **локально** по паролю, без сервиса.
- Другие профили: сообщение «Для LCP нужна официальная сборка прошивки».
- Загрузка (`/fulfill`) работает и без ключа.

## Заимствования (Apps > Мои заимствования)
Список защищённых книг, для которых на устройстве есть ключ (индекс `/.inkmod/lcp_loans.json`, пополняется при выдаче ключа, в том числе через `/api/lcp-unlock` и `/api/book-key`). Для каждой: срок («До 2026-03-01», «Без срока», «Срок истёк», «Дата не подтверждена» без достоверных часов).
- **Обновить ключ**: из книги читается `META-INF/license.lcpl`, по ссылке `status` берётся status-документ (LSD), по его ссылке `license` свежая лицензия (после продления она новая; id должен совпасть), затем повторный `/unlock` с сохранённым для провайдера хэшем пароля. Новый ключ и срок записываются. Если хэша нет, просит скачать книгу заново.
- **Вернуть книгу**: по `status` и ссылке `return` из LSD (шаблон `{?end,id,name}` раскрывается идентификатором устройства и его именем), запрос `PUT`; затем удаляется ключ. Требует второго нажатия: действие необратимо.
- **Проверить сервис LCP** (первая строка): доступность, зарегистрировано ли устройство, есть ли release-ключ в этой сборке.
Срок также показан в «О книге» (строка «Заимствование»).

## Ошибки
Офлайн, «устройство отклонено» (повторный 401 после новой регистрации), «ошибка сервиса» (5xx или непригодный ответ), «схема защиты не поддерживается» (422), неверный пароль, «нужна официальная сборка».

## Веб-API для плагинов
`POST /api/lcp-unlock {path, passphrase | userKey}` и `api.lcpUnlock(...)` работают локально (basic-профиль, либо готовый `userKey` от плагина). Это отдельный путь, сервис он не использует.

## Тесты
`test/lcp_unlock` (локальная разблокировка), `test/lcp_info` (лицензия, status-документ, возврат, даты), `test/download_sniff` (ответ сервиса с ошибкой не принимается за EPUB), `test/lcp_service` (запросы и ответы сервиса, обёртка ключа проверяется сквозным тестом с имитацией сервера на OpenSSL).
Не проверено: реальный обмен с lcp.freeink.org (из среды разработки сервис недоступен) и работа на устройстве.
