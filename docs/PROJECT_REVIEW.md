# Обзор InkOptimum: что реализовано, что нужно реализовать

Состояние на 2026-10-24 (сверка повторена, см. раздел «Сверка 2026-10-24» ниже; шапка ниже — по 2026-10-22). Сверено с репозиториями: evoll/InkOptimum (upstream, без новых коммитов с 517c8e7),
crosspoint-reader (a585ccbb, +27 коммитов с прошлой сверки), witchhunt-reader (3bfb9336, +191), Paperio-Reader
(8dca340e, GIF-код не менялся с 2026-08-21), Free-Ink/freeink-sdk (2c047df). Зависимости: ArduinoJson 7.4.3,
PNGdec 1.1.7, JPEGDEC (закреплён на HEAD), Arduino-wolfSSL 5.8.4 — новых версий нет.

Проверено только нативными тестами (432 из 432) и чтением кода. Сборка PlatformIO и прогон на устройстве не
выполнялись; всё, что трогает прошивку (пункты с пометкой «проверить на устройстве»), нужно проверить на X3/X4.

## 1. Реализовано

**Форматы и чтение.** EPUB (кэш секций v69, кэш CSS v16), FB2, FB3, DOCX, MOBI/KF8, RTF, HTML, Markdown (с таблицами),
TXT, XTC, PNG/JPEG/GIF/BMP в книгах и просмотрщике. Сноски с предпросмотром, закладки с именами, цитаты, статистика
чтения, KOReader-синхронизация (профили, процент без XPath), настройки отдельной книги, «Прочитано», разбиение
больших глав, словарь с поиском фраз и запасными формами слова, шрифты `.cpfont`.

**Библиотека и каталоги.** Library (индекс на SD), профили OPDS/KOReader (User-Agent, заголовки), ISBN/ASIN/серия,
редактор «О книге».

**Веб-портал.** Файлы (загрузка с сохранением старого файла при обрыве, имена в NFC), Заметки, Статистика, Погода,
Диагностика, Словарь, Шрифты, Обои, EPUB Kit. WebDAV с безопасной заменой файла. Файлы с паролями недоступны всегда.

**Сеть и безопасность.** wolfSSL 5.8.4 (запасной TLS-путь), докачка по Range, логин и заголовки KOSync не уходят на
другой сервер при редиректе, роуминг по самой сильной точке, защита от прошивки не той платы, откат OTA, BootHealth.

**Надёжность.** Отчёт о сбое с причиной, PC и адресом ошибки, защита от ZIP на 4 ГБ, проверка глубины PNG, серийные
команды без зависания цикла, безопасная замена файла (`lib/FileReplace`), оглавление: разреженный nav уступает NCX,
ссылки по имени файла, обложка в обёртке SVG/XHTML, `<img>` без расширения, наследование жирного/курсива блоков,
скрытие текста-водяных знаков.

**Средний приоритет — разобран 2026-10-23.** Ни один коммит witchhunt не накладывается на наш код автоматически.

Сделано:
- SSID на экранах Wi-Fi обрезается по ширине через `truncatedText`, а не по байтам (русские имена сетей резались посреди символа).
- Картинки сна: папка, в которой нет ни одного годного файла, больше не скрывает следующую (раньше пустая `/.sleep` оставляла `/sleep` неиспользованной). Порядок: выбранная папка, `/.sleep`, `/sleep`.
- Кэш CSS: стиль правила читается одним вызовом вместо ~30 обращений к SdFat на правило. Формат не менялся, версия кэша прежняя. Заодно исправлена константа размера записи (72 вместо 74 байт) и добавлен `static_assert`.

Уже есть у нас, переносить не нужно: окно «Индексация» с процентами (`ReaderActivity`, `Epub::load` с `onProgress`), переносы после дефиса и тире (`isExplicitHyphen`), заглушки картинок при нехватке памяти (`lowMemoryImagePlaceholder`), словарь без `.syn` (индекс готовит браузер).

Не делаем, с причиной:
- Ускорение первого открытия: **сделано** — обход центрального каталога ZIP окнами по 4 КБ (`lib/ZipFile/ZipCentralDirWindow.h`) и запись CSS-кэша блоками по 1 КБ (`lib/BufferedWriter`, формат не менялся). **Уже было у нас** — соответствие оглавления и spine за один проход через хеш-индекс (от 64 глав). **Не взято** — `f1dcbadf` (меньше аллокаций в разборе NCX, порядка десятков мс из 1,3 с; остальное — распаковка и XML) и промежуточный файл CSS: у нас правила копятся в памяти, копирования нет.
- FAT FSInfo (`f95ae746`): в проекте нет патчей SdFat, это правка стороннего кода без возможности собрать.
- Лестница памяти картинок и значок нехватки памяти: построены на TTF-шрифтах книги, которых у нас нет.
- Настройки без списка в куче (#4085, 10 КБ): переписывание SettingsList на обход, около 700 строк, без сборки слишком рискованно.
- Paperio 2.2.2 (2026-10-21) разобран: сделан запрет лишнего `loop()` активности при отложенном переходе (в том числе сне). Интервал строк у нас уже настраивается с шагом 1% и переопределяется для книги (`book_overrides`); отдельный ползунок — только удобство ввода. Сохранение страницы при быстром пробуждении у Paperio опирается на `syncWriteBufferFromDisplayed` и фоновую подготовку страниц, которых у нас нет; отложенного сохранения прогресса тоже нет, прогресс пишется сразу.

**Низкий приоритет: крупные подсистемы.** Отдельные проекты, каждый на недели. Делать только по явному запросу.

- Шрифты книги и TTF (разобрано 2026-10-24, **не начато**: растеризатор TrueType на устройстве, хранилище глифов, `TtfEpdFont`, правки `ParsedText`/`WordStore`/`FontCacheManager`, у crosspoint 43 файла и около 2000 строк и только на платах с PSRAM; без сборки и проверки на устройстве переносить это нельзя): семейства-акценты, режим SD, кернинг и лигатуры, журнал-кольцо хранилища глифов (десятки
  коммитов witchhunt за последние дни). У нас этого слоя нет: только `.cpfont` и страница «Шрифты».
- CJK: **сделано** kinsoku (`lib/CjkBreak`, правило применяется в `Hyphenator::breakOffsets`, 9 тестов). Остаётся: сетка и ширины знаков, интерфейс на китайском, японском, корейском, сжатые шрифты UI, ruby. Сам CJK-шрифт пользователь ставит как `.cpfont` через страницу «Шрифты».
- Фоновая подготовка страниц (№5), плагины на SD (№10), переработка TLS (№3) — отклонены раньше.
- crosspoint: AES-256 для манифестов, ограничение мощности WiFi, BLE-листалка, plugin-хаб. OPDS 2.0 сделан 2026-10-23 (`lib/Opds2`, 11 тестов); сервер выбирается по URL, заголовок Accept не отправляется, потому что его пришлось бы менять в общем загрузчике книг.
- Серийные тестовые команды (кнопки, состояние, хранилище глифов).

## folio-firmware (guloff), разбор 2026-10-24

Folio: личная прошивка для X4 Pro на базе CrossPoint 1.6.5 с iOS-приложением FolioLink. Что интересно:

| Функция | У Folio | У нас |
| --- | --- | --- |
| Переключение слота из прошивки | `OtaBootSwitch::switchTo` пишет свежую запись otadata мимо `esp_image_verify` | то же самое уже есть, плюс `switchToInstalled`, ручное переключение в настройках и диагностике, `rollbackCandidateMatches`, `rearmPending` |
| Откат | `esp_ota_mark_app_valid_cancel_rollback` через 10 с нормальной работы или перед сном | BootHealth: счётчик аварий в NVS, откат после 3 падений, подтверждение через 60 с, SD-восстановление |
| Проверка образа | заголовок, сегменты, XOR, SHA-256, chip_id, метка платы | то же самое (`FirmwareFlasher`) |
| Подпись образа Ed25519 | ключ в прошивке, `.bin.sig` рядом, подпись над `"FOLIO-FW-v1\n"+SHA-256`; OTA ставит только подписанное; SD-образ без подписи помечается «НЕ ПОДПИСАНО» | **добавлено как библиотека** (`lib/FirmwareSignature`, `lib/Monocypher`, `tools/sign_firmware.sh`, 7 тестов); в OTA и экран SD-обновления не подключено |
| Обновление из приложения | `POST /api/inklink/firmware/apply` принимает путь `/firmware/*.bin` только после проверки подписи; установка подтверждается кнопкой на читалке | загрузка по вебу и обновление с SD есть, подтверждения «прислано с телефона» нет |
| Экран подтверждения | показывает проект и версию из `esp_app_desc_t` образа (`readAppInfo`) | версия образа на экране SD-обновления не показывается |
| BLE-пульт и BLE-синхронизация | пульт листания, GATT-сервис с JSON-запросами, вход через HMAC-SHA256 от хеша токена и nonce | BLE нет (см. задачу BLE) |
| Прочее | PIN-блокировка и защищённые книги, сброс PIN подписанным запросом, календарь и цели чтения, заставки «Дашборд» и «Цитата», выделения, сборка без Bluetooth | не берём без запроса |

Подключение подписи (не сделано, нужны ваши решения и проверка на устройстве): выпустить ключ (`openssl genpkey -algorithm ed25519`), вписать публичный ключ (`tools/sign_firmware.sh --public-key`) в константу прошивки, подписывать релиз и загружать `firmware.bin.sig`; в `OtaUpdater` после `verifyStagedSha256` скачать `.sig` и вызвать `fwsig::verifyDigest`; на экране SD-обновления показывать «подписано / не подписано». Пока ключ нулевой, `keyConfigured()` возвращает false и поведение не меняется. Подробности: `docs/FIRMWARE_SIGNING.md`.

## OpenType/Indic-шейпер и формат ключей глифов (сделано)

- Движок: `lib/OtShaper` (witchhunt #603, лицензия в `COPYING`). Отличие от оригинала одно: `Face::Hooks` — cmap и advance берутся у FreeType, потому что у шрифта на карте cmap/hmtx в памяти нет (у CJK-шрифта это сотни КБ). - «Новый формат шрифта»: у нас нет собственного контейнера с glyph ID — TTF читается FreeType целиком, а у SD-шрифтов `.cpfont` нет GSUB. Вместо нового контейнера введено адресование глифов по ключу (`lib/Utf8/GlyphKey.h`): 31-битное «кодовая точка» = флаг + no-advance + dy(6) + dx(7) + glyph ID(16), шесть байт расширенного UTF-8 (лид 0xFD). Всё, что ходит по тексту через `utf8NextCodepoint`, переносит глифы как обычные символы; смысл ключу даёт только `TtfEpdFont::faultGlyph`. Чужие 6-байтные формы остаются невалидными (U+FFFD).

Таблицы GDEF/GSUB/GPOS читаются с SD по требованию (`FtFont::loadSfntTable`), буфер ~10 КБ; освобождаются в `releaseResidentCaches`.

- URL уходит в запрос без экранирования; `\r\n` в URL добавляет заголовок (plugin relay/fetch, href из OPDS). Нужно экранировать в одном месте — `sendRequest()` в SDK.
- Клиент, перестав читать ответ, блокирует веб-сервер на 10 с на каждый кусок (crosspoint #4285).
- DNS-ошибка при `connect(host)` даёт соединение на 0.0.0.0 и ожидание таймаута.
- Имена файлов длиннее ~150 символов CJK обрезаются в `/api/files` и getName() (буфер 500 байт).
- crosspoint: размер/занятость SD в «О системе» (#4331), зеркалирование скобок в bidi (#4295).

## Единый знаменатель: X4 Pro, X4 Classic, X3/X4 (07.11.2026)

Ядро одинаково для всех трёх (читалка, форматы, плагины, веб-сервер, синхронизации). Различия задаёт железо:

| Возможность | X4 Pro (S3) | X4 Classic (S3) | X3/X4 (C3) |
|---|---|---|---|
| PSRAM, векторные шрифты, FtShaper (индийские письменности) | да | да | нет (только bitmap-шрифты) |
| USB-накопитель (MSC) | да | да | нет |
| Подсветка, тач | да | нет | нет |
| BLE-листалка | профиль `kS3Profile`, ядро пересобирается | то же, что Pro | профиль `kX3Profile`, ядро пересобирается, контроллер только из flash |
| Датчик/IMU, RTC | нет | нет | X3 |
| Bidi/RTL, шрифты, форматы, плагины | общие | общие | общие |

Правило: функция живёт в общем коде и включается ёмкостью (`FREEINK_CAP_*`), а не веткой по плате.

### BLE-листалка на Classic и X3/X4
Реализуема. Наша `lib/BlePageTurner` — копия CrossPoint, отличались только правила NoBond/hasBond; они перенесены (пульт не выбран — радио не включается ни при открытии книги, ни по Home). Способ у CrossPoint и у нас один и тот же, «лучше» в нём нет, кроме настроек сборки: для C3 CrossPoint использует `firmware_tuned_c3` (пересборка ядра с `CONFIG_BT_CTRL_RUN_IN_FLASH_ONLY`, ROM libc и `patch_arduino_ble_controller.py`). Они повторены в окружениях `x3x4-ble` и `x4classic-ble`. **Не собрано и не проверено**: пересборка ядра в окружении разработки невозможна (недоступен реестр PlatformIO), на устройстве не пробовалось. Для S3 с USB-накопителем остаётся риск потери TinyUSB при пересборке ядра: проверить USB-режим перед использованием.

### Bidi/RTL, CPac, компактные записи глифов, IndicReorder
- Взят `lib/MiniBidi` из witchhunt целиком (классы, парные скобки, расширенные классы, арабская форма, метки-огласовки; зеркалирование скобок исправлено до разворота строки). Тесты witchhunt для minibidi перенесены и проходят.
- **Не перенесено**: построчный проход `BidiLine` (UAX#9 по всей строке, а не по слову), якоря огласовок и RTL-списки/таблицы. Они завязаны на их `ParsedText`/`TextBlock` и формат раздела; перенос — отдельная большая работа и требует затрагивать формат кэша. Нужно, если важны смешанные RTL/LTR абзацы с вложенными цитатами; для обычного арабского/иврита текущей реализации достаточно.
- CPac, компактные записи глифов и IndicReorder относятся к bitmap-шрифтам (`.cpfont`) на C3: нужны только чтобы на C3 без TTF показывать деванагари и т. п. У нас на S3 это закрывает FtShaper с настоящим OpenType-шейпером точнее и без новых форматов. Для C3 — отдельный проект (формат шрифта + предрасчёт GSUB). Пока не нужно; освобождение shaping-памяти в конце секции у нас не требуется, потому что FtShaper держит таблицы только на время сборки секции.

### Плагины
- **Dropbox**: `tools/plugin-hub/plugins/dropbox` (папки + загрузка книг). Сделано как страница плагина: вход по PKCE со своим App key, листинг, загрузка одной книги или всей папки. Не проверено на устройстве.
- **AlReaderX**: формат синхронизации не документирован (позиция и закладки в собственных файлах/сервере Neverland); публичных описаний нет. Реализовать «вслепую» нельзя. Нужны образцы файлов синхронизации (папка синхронизации AlReader) — тогда это обычный плагин чтения/записи позиции.
- **FBReader**: полная синхронизация с книжной полкой невозможна: вход через Google, закрытый API `books.fbreader.org`, позиция хранится в модели текста FBReader (абзац/элемент/символ), не переносимой на наш разбор. Возможен только обмен закладками/позицией по приблизительному проценту; книжная полка — нет.
