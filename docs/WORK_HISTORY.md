* **2026-11-11 (Paperio port: Native quantizer, PNG tone, `.pxc` sleep cache)** — (1) `lib/GfxRenderer/AdaptiveTone.h` (copied from Paperio-Reader; algorithm Totofaki, crosspoint #2861) is now shared by BMP and PNG; `Bitmap` uses it. (2) `Gray4QuantizationMode {DisplayTuned, Native}` + `quantizeNative()`; Atkinson/Floyd-Steinberg ditherers take the mode; a tone-mapped image is quantized with evenly spaced levels (0/85/170/255) because the tuned thresholds would compensate a second time (idea: Paperio `4bad1771`). (3) PNG sleep images (Paperio `d76275c`): `RenderConfig::adaptiveTone/tonePoints`; `PngToFramebufferConverter` runs a best-effort histogram pass (extra PNGdec decode, every 4th row), then applies the tone to the source row in both the PNGdec and the streaming paths. X4 Pro keeps its own halftone path (tone still applied to luminance). (4) `.pxc` sleep cache (Paperio `c0f6a456`, own implementation): `/dir/.name.png.<srcsize>.t<0|1>.pxc` written by the decoder on first sleep, replayed with geometry and size validation (invalid file is deleted) on later sleeps. Source size and tone flag are in the name; an image replaced by another of exactly the same size would reuse the old cache (delete the `.pxc`). Old caches of replaced images are not cleaned up. 6 new native tests (`test/adaptive_tone`); 916 tests pass; x4pro-release builds; not tested on device.
