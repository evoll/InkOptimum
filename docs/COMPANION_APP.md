# InkOptimum Companion — план приложения-компаньона (Windows / Linux / macOS / Android / iOS)

Цель: тот же функционал, что у FolioLink для Folio (guloff/folio-firmware, см. FEATURE_MATRIX §3a), но для нашей прошивки и сразу на пяти платформах. Статус: **план и разбор состояния прошивки (2026-11-23)**, кода приложения ещё нет; Flutter/Dart в этой среде не установлен, поэтому сборки и тесты приложения делаются отдельно (CI).

## 0. Статус этапа 0 (2026-11-24)
Сделано в прошивке (не проверено на устройстве): `lib/CompanionAuth` (сопряжение 6-значным кодом на 120 с, блокировка на 5 мин после 3 неверных, токены 32 байта, на устройстве хранится только SHA-256, до 8 устройств, файл `/.crosspoint/companion_tokens.txt`), `src/network/CompanionApi.{h,cpp}`: `GET /api/v1/info` (открытый), `POST /api/v1/pair/start`, `POST /api/v1/pair/confirm {code, deviceName}` → `{token}`, `GET /api/v1/devices`, `POST /api/v1/devices/revoke {id}` (оба по Bearer). Код показывается на экране «Передача файлов» (`STR_COMPANION_PAIR_CODE`), mDNS-сервис `_inkoptimum._tcp` порт 80. Нативные тесты: 9. **Ещё не сделано:** старые `/api/*` и WebDAV по-прежнему открыты (веб-интерфейс работает без токена); отдельный экран «Связь с телефоном»; подпись запросов HMAC; остальные `/api/v1/*` (книги, сессии, полки, словарь…).

## 1. Что уже есть в прошивке (находка)
Веб-сервер InkMODWebServer уже отдаёт почти всё, что нужно приложению: `/api/status`, `/api/stats`, `/api/files` + загрузка/переименование/перенос/удаление, `/api/notes` (закладки, клиппинги, переименование/удаление), `/api/settings` (GET/POST), `/api/fonts*`, `/api/dictionaries*`, `/api/wallpapers/apply`, `/api/wifi*`, `/api/weather*`, `/api/opds*`, `/api/koreader/profiles*`, `/api/plugins*`, WebDAV, mDNS (`hostname.local`).
**Чего нет:** (1) любой авторизации — API открыт всем в сети, пока включена «передача файлов»; (2) постоянного режима «связь с телефоном» (Folio держит его отдельным экраном); (3) полок и статусов, личного словаря, журнала сессий с экспортом, списка скриншотов, выбора заставки/подписанного OTA из приложения; (4) BLE-синхронизации (BLE у нас только как пульт, `BlePageTurner`).

## 2. Выбор технологии: Flutter (Dart)
Один код под все пять платформ, нативные Bonjour/mDNS и BLE-плагины, у автора уже есть Flutter-приложение (iButton). Альтернативы (Tauri + отдельно мобильные, Kotlin Multiplatform) дают больше кода на платформу. Решение: Flutter 3.x, пакеты — `dio` (HTTP), `multicast_dns`/`nsd` (поиск), `flutter_blue_plus` (BLE; на Windows/Linux — экспериментально, см. риски), `drift` (кэш SQLite), `riverpod`, `cryptography` (HMAC/SHA-256, проверка Ed25519), `file_picker`.

## 4. Протокол v1 (черновик)
* Транспорт: HTTP по LAN, JSON UTF-8, версия в пути `/api/v1/*`; старые `/api/*` остаются для веб-интерфейса.
* Авторизация: GET статистики/книг — по токену тоже (в отличие от Folio, где чтение открыто); токен хранится у устройства как SHA-256, у приложения — в защищённом хранилище ОС. Сопряжение: приложение шлёт `POST /pair/start`, читалка показывает 6-значный код 120 с, `POST /pair/confirm {code, deviceName}` → `{token}`. Три неверных кода — блокировка на 5 мин.
* Запрет «нашёл в сети — управляет»: без токена только `GET /api/v1/info` (имя, версия, плата).
* Дельты: `since` (epoch) и `offset/limit`, `more/nextOffset`, как в Folio.
* BLE (этап 4): сервис с запросом/ответом и HMAC-SHA256 challenge, кадры `[seq u16][flags][payload]` — формат Folio можно взять как образец, UUID свои.
* HTTPS нет (ресурсы ESP32): токен в LAN в открытом виде; для защиты от подслушивания Wi-Fi — HMAC каждого запроса (`X-Ink-Sig` = HMAC(token, метод+путь+время+тело)) — решить на этапе 1.

## 5. Платформенные особенности
* iOS: ключ `NSLocalNetworkUsageDescription` и `NSBonjourServices`; фон — только BLE/по запросу. Публикация в App Store требует аккаунта разработчика; TestFlight/сайдлоад.
* Android: `CHANGE_WIFI_MULTICAST_STATE` для mDNS, `NEARBY_WIFI_DEVICES`/BLE-разрешения; APK из CI.
* macOS: sandbox-entitlements `com.apple.security.network.client`, Bonjour; подпись/нотаризация для распространения.
* Windows/Linux: mDNS через `multicast_dns` (Bonjour на Windows не обязателен); BLE через `flutter_blue_plus` нестабилен — на десктопе этап 4 можно пропустить; пакеты MSIX/AppImage/deb.
* Ввод ссылки `inkoptimum.local` вручную — запасной вариант, если mDNS блокируется роутером.

## 6. Этапы
0. **Прошивка**: `/api/v1/info`, сервис Bonjour, сопряжение и токены, режим «Связь с телефоном» (экран + автозапуск Wi-Fi). Нативные тесты на разбор/проверку токенов.
1. **Каркас приложения**: поиск, сопряжение, раздел «Книги» (список, загрузка, удаление), «Статистика», «Выделения». CI-сборки на 5 платформ (GitHub Actions: ubuntu/windows/macos runners).
2. **Данные Folio-класса**: полки и статусы, личный словарь, скриншоты, heatmap, экспорт заметок.
3. **Управление**: заставки, настройки, шрифты, словари, OTA с проверкой подписи.
4. **BLE** (мобильные платформы): фоновая синхронизация, HMAC-вызов.
5. Локализация RU/EN, документация, релизный пайплайн.

## 7. Риски и решения
* Нет авторизации сейчас — этап 0 обязателен до любого приложения, иначе приложение расширит уже открытую поверхность.
* Память ESP32-C3 (X3/X4): режим связи занимает Wi-Fi + веб-сервер; на C3 полки/словарь хранить в JSONL с потоковой выдачей, без загрузки целиком.
* Нет Flutter в среде сборки: проверка приложения делается в CI/на машине автора; в архивах прошивки каталог `companion/` отдельно.
